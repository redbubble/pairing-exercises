# Redbubble Fullstack Code Pairing Exercise

Welcome to the fullstack code pairing exercise!

## Context

This repository offers you the choice between three languages (Go, Javascript, or Ruby).
Please select the option you are most comfortable with during the pairing session with our engineers.

Each language has its own incomplete implementation of a
[Price Calculator app](functional-requirements),
which we'll use as the basis for our fullstack pairing exercise.

## Interview Setup & Instructions

Please check which interview stage you are completing today and follow the instructions below:

### 🔹 Stage 3.1: Technical Walkthrough & Test Cases Exploration
* **Before the interview:** No prep required! You do not need to set up or complete any code prior to the session.
* **During the interview:** 
  - We will share the repository link live during the first few minutes of the call. You'll clone it and open it in your preferred IDE.
  - You'll share your screen and walk us through the high-level codebase structure, workflow, and business logic.
  - Followed by the walkthrough, we'll discuss the edge cases and testing strategy.
* **Note:** You will **not** be asked to implement any incomplete methods or feature logic during Stage 3.1.


### 🔹 Stage 3.2: Technical Implementation & Pairing
* **Before the interview:** Please set up the code on your machine before the session (**however, please don't complete the exercise beforehand**).
  - Clone this repo. For the fullstack interview, you can pick either:
    - [Go](go/price-calculator/README.md)
    - [Javascript](js/price-calculator/README.md)
    - [Ruby](ruby/price_calculator/README.md)
  - Set up the app in your IDE of choice. You will be sharing your screen during the pairing interview.
  - Make sure you can build and run the code.
  - Familiarise yourself with
    - Code structure
    - Tests
    - Design choices
    - [Business logic](functional-requirements)
* **During the interview:** We'll pair on implementing missing functionality, resolving tests, and discussing design choices.

## Final Words

We won't be testing your language knowledge, but rather how you work with us to solve interesting problems. We had fun creating this exercise! It's not perfect, and we'd love to hear how you'd improve it.
